# Plan: Broad Shallow Screening Engine (Revised)

## Problem Statement
My prior plan created 8 separate per-criterion tasks (TASK-016..023), each a deep implementation of one criterion (education, experience, CAD, pressure systems, etc.). This is wrong for two reasons:

1. **Exponential growth**: for each job type there will be dozens of criteria → code explosion. The user said exactly this ("می‌دونی اگه برای هر شغلی انقدر ریز بشیم چقدر زیاد می‌شه")
2. **Corpus limitation**: the system must work beyond "jobs + candidates". It should screen against any corpus — job requirements, product specs, technical portfolios, evaluation rubrics, even medical or legal rules.

## Revised Approach: Generic Screening Engine

### Design
Create a single generic screening engine that operates on any domain-specific corpus:

```
SCREENING ENGINE
├── Extractor        - LLM extracts structured competency requirements from unstructured text
│   └── requirements matrix: [{skill, category, weight, required}]
├── Evaluator        - Scores a candidate profile (or any record) against the matrix
│   ├── Per-skill match fraction
│   ├── Weighted overall score
│   └── Matched/unmatched verdict per requirement
└── Shortlist        - Rank top-N by weighted overall score
```

This is the standard agentic pattern: model extracts structure, computes metric, returns result. It's proven and testable with BDD.

### Key properties
- **Domain-agnostic**: works on Mechanical Engineering, Oil & Gas, Medical, Legal, Generic skills — just pass different unstructured input text
- **Shallow**: one generic extractor + one evaluator, no hardcoded criteria tables
- **Composable**: all criteria live in one extractor call — add new domain without new code
- **LLM-extracted**: requirements are parsed by MimoAdapterClient tool-call (enrich_and_extract_profile style), not handcoded SQL filters
